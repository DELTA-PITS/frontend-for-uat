5. Identity Root Cause

The missing issuer_id is not merely a production configuration drift. A fresh Keycloak 26.6.2 import from the repository's own realm-export.json reproduced the same missing sub claim. Adding one protocol mapper caused sub to appear; removing it caused the claim to disappear again. This establishes a reproducible provisioning root cause.

Paper implication: source verification should not be described as fully achieved while publisher identity attribution is empty in registry records. The provenance of content is demonstrable; attribution to a specific publisher identity is not currently reliable.

6. Multi-Publisher Isolation

With Publisher A and Publisher B authenticated independently, each publisher's GET /records response included the other publisher's records. Leaked fields included record ID, content hash, filename, transaction hash, created_at and issuer_id. This elevates the earlier single-account inference into direct two-account runtime evidence.

8. Resilience

  • Postgres unavailable during registration → 500; no partial row observed after recovery.
  • Keycloak unavailable → new logins fail; already-issued token can still validate while cached JWKS remains valid.
  • Anvil unavailable during register/verify → 500 propagated.
  • Backend container restart preserved committed Postgres data.
  • Anvil restart lost previous transaction history because the configured chain is ephemeral/in-memory.

10. Remaining Gaps

  • More aggressive barrier-synchronized concurrency to maximize the duplicate-registration race window.
  • True validly-signed wrong-issuer / wrong-audience JWT using a second realm/signing key.
  • Pending-transaction behavior under non-instant Anvil mining.
  • Frontend/backend network-failure UX in the final local stack.
  • Accessibility, real mobile devices, and full disaster-recovery drill.
  • Historical Locust figures cannot be fully reconstructed from available raw evidence.
