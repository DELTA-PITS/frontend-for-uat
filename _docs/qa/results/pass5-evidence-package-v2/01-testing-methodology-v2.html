1. Purpose

The independent QA was designed to determine what the PITS prototype demonstrably does, distinguish source-level assumptions from runtime evidence, reproduce the paper's technical claims where possible, identify defects without hiding them, and then verify targeted remediation without erasing the original baseline.

V2 principle: a post-fix PASS does not rewrite history. V1 remains evidence that defects existed; V2 adds evidence that selected defects were remediated and regression-tested.

5. Result Rules

  • PASS: executed behavior matches the pre-stated expected behavior.
  • FAIL: executed behavior does not match expected behavior.
  • SKIP/BLOCKED/XFAIL: not fully executed due documented precondition/environment or expected unresolved state.
  • INCONCLUSIVE: evidence insufficient to attribute a failure.
No universal pass rate. Unit, live historical E2E, real-local integration and performance requests are different evidence types. The 53/53 figure applies specifically to the post-fix Pass-5 integration suite.

6. AI and Human Roles

Claude Code was used as an AI coding/testing agent under Laksa Ersa's direction to inspect code, write/execute tests and document outputs. It is not described as an independent human reviewer. Runtime claims come from actual test execution and infrastructure interactions, not generated numbers.

7. Safety / Reproducibility

The final integration and regression work used a disposable local stack. Destructive resilience actions were restricted to local services. Production deployment state is documented separately from repository/local correctness.

8. Limitations

  • No formal penetration-test claim.
  • No citizen trust/outcome study.
  • No public-chain durability claim; Anvil is a local dev chain.
  • Accessibility, real-device and full DR remain incomplete.
  • Historical paper performance figures remain internally inconsistent and cannot be reconstructed exactly.
  • No post-fix Locust rerun was performed.
