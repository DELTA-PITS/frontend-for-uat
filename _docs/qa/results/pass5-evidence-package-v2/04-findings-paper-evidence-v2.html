2. Recommended Results Framing

“Following independent QA, targeted remediation was implemented and evaluated on a freshly rebuilt full-stack environment using real PostgreSQL, Keycloak, and Anvil components. The complete 53-case integration suite subsequently passed without failures or skips. Regression testing confirmed publisher-specific record isolation, non-empty publisher identity attribution, controlled handling of malformed bearer tokens, filename-length validation, and pending-transaction behavior. The end-to-end provenance path continued to pass, with the authenticated publisher's token subject matching the stored issuer identifier.”

3. Mandatory Production Qualification

“At the time of the post-fix QA freeze (14 Sep 2026), the identity-provider configuration change had been applied to production, but the backend application-code fixes had been verified only in the repository/local integration environment. On 21 Sep 2026 the backend fixes were deployed to production and spot-checked live (controlled 401 for a malformed token, 400 for an over-long filename, and record listing filtered by publisher identity); a full live end-to-end and two-publisher retest on production was not yet performed.”

4. Interpretation

The most defensible academic narrative is not “PITS was always 100% correct.” It is that independent QA validated the provenance core, exposed specific weaknesses in identity/authorization/error handling, and a subsequent remediation cycle produced a clean 53/53 real-local integration regression result. This is stronger evidence because it preserves both discovery and correction.
